Paso 5: Comparación de arquitecturas PHP vs JSP

Diferencias de ciclo de vida, gestión de memoria, despliegue y escalabilidad.

AspectoPHP (Apache + mod_php/FPM)JSP (Apache Tomcat)
1. Ciclo de vida
Modelo de ejecuciónInterpretado. Cada petición ejecuta: Parse → Execute → Output, y el script termina.El JSP se traduce a un Servlet, se compila y se instancia una sola vez. Luego atiende peticiones con service() hasta destroy().
Primera peticiónRápida: solo se interpreta (con OPcache queda cacheado).Más lenta: traducción y compilación. Las siguientes peticiones son muy rápidas.
Estado entre peticionesStateless ($_SESSION guardado en archivos del servidor).Stateless (HttpSession guardada en memoria del contenedor).
2. Gestión de memoria
Memoria por petición"Shared-nothing": todo se libera al terminar la petición.El servlet permanece en memoria; los objetos los administra la JVM con recolector de basura (GC).
ConcurrenciaUn proceso o worker por petición.Una sola instancia del servlet atendida por múltiples hilos (threads); requiere código thread-safe.
ConsumoBajo y predecible por petición.Mayor base (JVM), pero eficiente bajo carga alta.
3. Despliegue
Cómo se despliegaCopiar archivos a htdocs/lab09/. Sin compilar ni reiniciar.Copiar carpeta o .war a webapps/lab09/; Tomcat lo despliega solo. Se configura con WEB-INF/web.xml.
RequisitosApache + PHP (XAMPP).JDK + servlet container (Tomcat).
Puerto en este lab808080
4. Escalabilidad
Escalado horizontalMuy sencillo: más servidores detrás de un balanceador (sesiones en Redis o BD).Posible con clustering de Tomcat y replicación de sesiones, o balanceador con sesiones sticky.
Escalado verticalMás workers (PHP-FPM) y RAM.Más hilos y heap de la JVM.
Uso típicoSitios y aplicaciones web rápidas de desarrollar.Aplicaciones empresariales de gran tamaño.
